# FastPeek · 塞进 U 盘就能用的看图器

一个 282 KB 的原生 Windows 程序，双击就开，没有安装包、没有浏览器、没有后台服务。
插上 U 盘、双击 exe，它先把这支 U 盘里的**相册做成一张张封面卡片**铺出来，
点进去就是那个相册的照片，再单击就是大图。

![缩略图网格](docs/01-grid.png)

## 为什么比之前的网页版快

上一版走的是「本地 HTTP 服务 + 浏览器」，慢在启动链路：起 Python → 起 Web 服务 →
拉起浏览器内核 → 加载页面框架 → 才开始读文件。一个环节都不能省。

这一版整条链路只有一个进程：

| | 网页版 | FastPeek |
|---|---|---|
| 运行时依赖 | Python + 浏览器（约 200 MB 内存起步） | 无，静态链接，只有系统 DLL |
| 显示第一帧 | 1.5–3 秒（浏览器冷启动） | **31 ms**（实测） |
| 扫描 800 个文件 / 40 个目录 | 0.4 s 左右 + 页面渲染 | **188 ms**（后台线程，界面不卡） |
| 扫描 15030 个文件 / 126 个目录 | 十几秒 + 页面明显卡顿 | **78 ms 全部就绪**（后台线程） |
| 进程常驻内存 | 200–400 MB | 25–60 MB（大图预加载峰值最多再加 96 MB） |
| 分发 | 一整个文件夹 | 单个 `FastPeek.exe` |

自己的渲染循环，所以滚动、缩放、切图都是即时的，没有浏览器那种"等一下再重排"的感觉。

## 不损耗 U 盘

这是设计时最优先的一条，五个具体做法：

1. **不写任何一个字节到 U 盘。** 缩略图、解码结果全在内存里，退出即释放。
   没有 `.thumbcache`、没有临时文件、没有隐藏目录。
2. **只读打开。** 图片用 WIC 以 `GENERIC_READ` 打开，视频交给系统解码器播放，
   全程不产生写操作，U 盘的闪存擦写次数不会被这个软件消耗。
3. **按需解码。** 只解码屏幕上真正看得见的格子，解码在后台线程里排队做，
   滚动时不会为了"预生成全部缩略图"而把整支 U 盘读一遍。大图只额外预取
   **前后各一张**，而且只在看大图时进行，离开就停。
4. **只往下扫两层子文件夹。** 扫描不到三层以上：点开一个盘或一个大目录，
   走两层就停（见下文「扫描的范围」），不会为了建索引把整支盘从头读到尾。
5. **配置写在电脑上。** 窗口位置、上次目录存在本机
   `%LOCALAPPDATA%\FastPeek\settings.ini`，换台电脑也不会污染 U 盘。
6. **缩略图缓存也留在本机。** 第一次看某张图会解码，之后把缩略图写到本机
   `%LOCALAPPDATA%\FastPeek\thumbs\`（以文件路径做键）。下次再打开同一目录，
   滚到看过的图就直接读缓存，不用重新解码——这是资源管理器"秒开"的同款思路。
   缓存完全在电脑上，U 盘依旧只读不写。

## 怎么用

**最快的方式**：把 `FastPeek.exe` 复制到 U 盘根目录（或者照片文件夹里），双击。

- 拖一个文件夹到窗口上 → 换目录
- 命令行：`FastPeek.exe "D:\照片"` 或 `FastPeek.exe "D:\照片\IMG_0001.jpg"`
- 顶部「打开文件夹」按钮 → 选任意目录
- 顶部「↑」→ 回上一级
- 顶部「子文件夹 / 缩略图」→ 在卡片和文件网格之间切换；卡片上右键（或 `Esc`、`Backspace`）退回上一级
- `Ctrl+F` 或 `/` → 输入文件名即时筛选，`Enter` 完成编辑，`Esc` 清除
- 顶部「名称 / 时间 / 大小」→ 循环切换排序方式（设置会记住）
- 网格或卡片视图里 `Ctrl+滚轮` → 调整缩略图大小（60%–180%，设置会记住）
- 大图里按 `S` → 全屏幻灯片；`空格` 暂停/继续，`[` `]` 调整间隔

**启动时打开什么**，按优先级：

1. 命令行给了路径 → 打开它；
2. 上次看过的目录还在 → 接着打开它（存在本机 `settings.ini`）；
3. 都没有 → **打开一个空白窗口**，等你拖文件夹进来或按 `O` 选目录。

它不会自作主张去扫描 exe 所在的目录——看图器不该因为"恰好被解压到某个盘"就乱翻那里。

## 界面

![大图](docs/02-single.png)

- **缩略图网格**：**单击任意格子直接进入大图**（悬停时格子会浮起来、光标变手型），
  透明 PNG 走棋盘格背景，手机竖拍照片按 EXIF 方向自动转正。
- **子文件夹视图**：扫描完只要当前目录里有子文件夹，就先列出**每个子文件夹一张方形卡片**。
  卡片上铺的是那个文件夹里的一张照片当**封面**（按卡片比例居中裁切），
  右下角的小标签是里面的文件数。封面只取一张，是为了别为一屏卡片读几百个文件：
  一张封面就是一次解码，四宫格拼图是四次。
  **单击卡片进入**，网格里就只剩这个子文件夹自己的文件；
  **右键 / `Esc` / `Backspace` 后退一级**，回到上一层的卡片列表——而且是回到**原来那一行**，
  不是重新从顶部开始（进过哪些网格、滚到哪儿，都记着，退回来原地复原）。
  排在最前面的「整个文件夹 · N 个文件」卡片是"这个目录连同子目录的全部文件"的平铺视图，
  也就是原来那种一屏铺满的看全部，随时都能回到那里。工具栏「子文件夹 / 缩略图」可以手动切换。

  ![子文件夹](docs/04-folders.png)

  卡片封面和解码过的缩略图**共用同一套内存缓存**：从卡片点进去，那张图已经在
  RAM 里，不用再读盘，所以"进相册"是瞬间的。

## 扫描的范围

**只往下扫两层子文件夹**（`SCAN_MAX_DEPTH`）。这一条是刻意的上限，不是懒：
误点一个盘、或者点进 `C:\Users`，递归到底就是几万个目录、十几万个文件，
盘会被读得吱吱响，窗口也会被 indexPath 拖住好几分钟。

现在的代价是可预期的：

```
C:\      走 239 个目录就停，跳过 31441 个目录      耗时 ≈ 50 ms
D:\      走  35 个目录就停，跳过    91 个目录      耗时 ≈ 50 ms
D:\...\aaa（4360 个相册、18869 张照片）  没被截断   耗时 ≈ 200 ms
```

- **边界上会明说**：进到第 2 层的文件夹时，状态栏会补一句「只扫到 2 层」。
  否则那里只剩文件、看不到子文件夹，很容易被当成"程序坏了"。
- **要更深就换根**：在那个文件夹里按 `O`，选择框会直接开在**当前目录**
  （不是"此电脑"），挑一个更深的文件夹打开，它就成了新的根，再带两层。
  也就是说：想看的目录，永远离你只有一次 `O`。
- 想改这个数字就改 `src/app.h` 里的 `SCAN_MAX_DEPTH`（0 = 只看当前目录，
  24 就是原来的"整个树都扫"）。`--bench` 日志里的 `cut=` 会告诉你截掉了多少目录。

- **格式筛选**：工具栏最右侧（「资源管理器」旁边）的按钮，点一下在
  **全部 → 图片 → 视频**之间循环。只显示某一类文件，翻页、编号、计数都跟着变；
  正在看的大图如果被筛掉，会自动跳到过滤后的第一张。
- **搜索**：`Ctrl+F` 或 `/` 开始在工具栏右侧输入，文件名**包含**输入内容就留下，
  不区分大小写；网格、翻页、计数和子文件夹卡片（含封面与徽标）都按同一条件收窄。
  `Enter` 结束编辑但保留筛选，`Esc` 清空。搜索是内存里的过滤，不会重新读盘；
  切换目录会自动清空。
- **排序**：点顶部「名称 / 时间 / 大小」循环切换。名称走自然排序（`photo 2` 在
  `photo 10` 前面），时间最新在前，大小最大在前；同值时按路径稳定排列。
  排序只改视图顺序，扫描和缩略图缓存都不受影响，设置会跨启动保留。
- **缩略图密度**：网格或卡片视图里按住 `Ctrl` 滚滚轮，格子从 60% 到 180% 缩放，
  一屏能放多少张由你决定；选中项会被保持在可见范围内，大小也会记住。
- **相邻图预加载**：进入大图后，后台会悄悄把**上一张和下一张**也解码进内存
  （每张最多 48 MB，两格合计最多 96 MB；超大的图自动跳过）。
  按 `←` `→` 时如果目标已经准备好就直接换像素，不再等 WIC。预加载会核对
  **路径 + 大小 + 修改时间**，扫描中途插入文件、重新扫描或换了目录都不会串图。
- **信息浮层**：大图里按 `I`，左下角显示文件名、像素尺寸、文件大小、格式、
  修改时间和完整路径，再按一次关闭；切到视频时不覆盖画面。
- **复制**：大图里 `Ctrl+C` 把当前图片按 24 位 DIB 放进剪贴板（透明区域按
  棋盘格的底色处理），不在大图或没有解码成功时则复制文件路径；
  `Ctrl+Shift+C` 永远复制路径。
- **视频封面**：视频格子显示的是**真实画面**（大约片长 1/10 处的那一帧，
  避开开头的黑场和淡入），叠一个半透明播放按钮和「视频」标记。
  这一帧由后台线程去取，取不到（缺解码器、文件损坏）就退回纯黑卡片加播放按钮。
- **大图**：滚轮缩放（以鼠标位置为锚点），按住拖动平移，
  「适合窗口」不会把小图放大糊掉，`1:1` 是真正的原始像素。
  画面左右两侧各有一个半透明圆形箭头，鼠标移上去会亮、点一下就翻页；
  第一张/最后一张时对应的箭头变暗（点了也不会跑位）。
  在大图里**点右键**、双击或按 `Esc` 都能退回网格；右键会把全屏一起退掉，
  不会把人留在"全屏网格"里找不到出口。视频画面上右键同样有效。
- **视频**：直接嵌入窗口播放（系统 Media Foundation / EVR），有声音。
  系统缺解码器时会提示按 `E` 用系统播放器打开。视频画面会给两侧箭头让出通道，
  不会把按钮盖住。播放时底部状态栏会变成一条**进度条**：点击或拖动滑块即可
  跳转到任意时间点，左边是已播放时间，右边是**剩余时间**（`-mm:ss`）。
  `+` `-` 调音量（0–100，设置会记住），`M` 静音/恢复，`Shift+←` `Shift+→`
  快退/快进 10 秒。音量 0 就是静音——MFPlay 本身没有独立的 mute 标志。
- **幻灯片**：大图里按 `S`（或工具栏「幻灯片」）进入全屏播放，默认每 5 秒一张；
  `空格` 暂停/继续，`[` `]` 把间隔调成 1–60 秒（会记住），`Esc` 或再按 `S` 退出。
  手动按 `←` `→` 会重新开始计时，不会刚翻过去就立刻被切走；放到最后一张自动停下。
  下一张是视频时也停下并留在该视频上——片子有自己的时长，幻灯片不该把它掐断；
  播放中直接点进视频同样会结束幻灯片。

### 记住的设置

全部写在 `%LOCALAPPDATA%\FastPeek\settings.ini`，不碰源目录，也不碰 U 盘：

| 键 | 含义 | 默认 |
|---|---|---|
| `view\sort` | 排序：`0` 名称 / `1` 时间 / `2` 大小 | `0` |
| `view\thumbScale` | 缩略图大小百分比（60–180） | `100` |
| `view\slideSec` | 幻灯片间隔秒数（1–60） | `5` |
| `video\volume` | 视频音量（0–100） | `100` |
| `video\muted` | 是否静音 | `0` |

## 实测数据

自己跑一遍就能复核（结果写到 `%TEMP%\fastpeek-bench.txt`）：

```
FastPeek.exe --bench "D:\照片"
→ first_frame=32 ms
→ scan_done=188 ms items=800 dirs=40
```

要看**网格滚动**的帧时间，用这两个（会自己滚动、记录、然后退出）：

```
FastPeek.exe --scrollbench "D:\照片"   # 模拟连续甩动
FastPeek.exe --scrollslow  "D:\照片"   # 一格一格慢慢滚，每次停顿都会触发新解码
```

上万文件那一档（15030 个文件 / 126 个目录）：

```
→ first_frame=31 ms
→ walk_done items=15030 dirs=126 cut=0 yield=0 eps 0 ms   （停在相册列表，不给图片让路）
→ sort=31 ms n=15030          （排序在后台线程，UI 不参与）
→ scan_done=78 ms paints=3 avg_paint=15 ms worst_paint=16 ms
→ thumb cache: decodes=24 bytes=4860000 slotsUsed=24 items=15030
```

也就是说：15030 个文件全部就绪只用 78 ms，这期间只重绘了 3 帧、最慢一帧 16 ms；
缩略图只解了屏幕上那 24 格（合 4.86 MB 内存），没有任何一张被挤掉重解。
翻页滚动实测 16 ms/帧（约 60 fps）。

视频封面单独一档（24 个视频挤满一屏，是最坏情况）：

```
→ paints total=35 avg=4 ms worst=16 ms        （界面完全不受影响）
→ thumb total_decode=1900 ms decodes=24 avg_decode=79 ms bytes=3411072
```

一帧视频封面要 79 ms——把它放在绘制线程里会变成 avg 70 ms / worst 187 ms 的灾难。
现在它跑在后台线程：24 张封面用 1.9 s 陆续补上，格子先显示黑色卡片加播放按钮，
缓存总共 3.4 MB（142 KB/张）。

图片缩略图原来是在**绘制线程里**解码的：每帧最多花 9 ms，但"至少允许一次解码"，
所以一张 40 ms 的大图就是这一帧卡 40 ms——一屏 24 格没加载过，就是 24 次卡顿。
现在和视频封面走同一条路：**绘制只负责 blit 和占位符，解码交给后台线程池**，
每张图回来时发一条消息补画对应的格子，滚动始终是纯 blit。

只把**解码**挪走还不够：磁盘缓存的**读**（`ThumbGet` 里）和**写**（每张图落地时）
原来都还在 UI 线程上，一次一个 150 KB 的 CreateFile + ReadFile/WriteFile，加上
杀软对每个新文件的扫描，一屏 24 格就是 24 次磁盘往返——几千个子文件夹往下拉
就会一格一格地卡住。现在缓存的读、解码、写全在后台线程里完成，**绘制路径不碰磁盘**。
请求队列也收紧了：只留两屏（64 格）的待解队列，满了就丢掉最旧的一条——那是最可能
已经滚出屏幕的格子，绝不让它挤掉用户正看着的那一格。U 盘上这直接意味着
"翻很久之后它还在读你早就划过去的文件"这种情况不会再发生。

线程数按介质自动选：本地盘 2 个（一屏没加载过的图大约一半时间填满），
**U 盘只给 1 个**——一个 U 盘同时服务两条读流反而更慢，控制器要在两个文件之间来回找位置。
这也是这个程序对 U 盘的唯一姿态：**只读**。解码结果写到
`%LocalAppData%\FastPeek\thumbs`（本地盘），不落在 U 盘上；重复打开同一支盘，
缩略图直接从本地缓存读，U 盘一次都不用碰。

顺带说清"寿命"这件事：闪存的寿命只被**擦写**消耗，读多少次都不磨损。这个程序
对 U 盘零写入——不建缩略图、不写配置文件（`settings.ini` 也在 `%LocalAppData%`）、
不留临时文件，所以它读多少遍都不会让盘变短命。

子文件夹视图单独量了一档，专门针对"几千个子文件夹往下拉就卡"这个场景
（1200 个子文件夹 / 3600 张图，每个文件夹都没缓存过，一格一格慢慢滚 200 次）：

```
FastPeek.exe --scrollslow "D:\相册目录"
→ scroll wall=52781 ms paints=681 avg=7 ms worst=16 ms decodes=832
→ thumb decodes=832 cache_hits=820 bytes=26 MB（160 格内存缓存全满）
```

50 秒里新解了 832 张封面、写了 832 个缓存文件，最慢的一帧仍然是 16 ms——
也就是说"往下拉"的过程中每一格都是新图，界面也没有任何一帧停住。
早期版本的同一场景是每解一张卡一帧（一屏 24 格连续卡 24 次），
后来又发现缓存的写还留在 UI 线程上，卡顿就从"每格 40 ms"变成"每格一次磁盘写"。

卡片本身在绘制时不做任何 I/O：它画的是已经在内存里的封面，滚过去还没解出来的
格子先留空格，后台解完立刻补上——U 盘依旧是只读的，也不会被来回读已经滚过去的位置。

**扫描给图片让路。** 一根 U 盘只有一条读队列，扫描每读一个目录，都在往用户正等的
那张图前面插队——所以"一边扫整棵树、一边点进相册"时，出图会明显变慢。
现在每张缩略图（以及每张大图、每个视频首帧）开始读之前都会打一个时间戳
（`ThumbTouchBusy`），扫描线程在每个目录之间检查它：只要图片还在读，就先让开，
等到屏幕安静 0.9 秒才继续走（`THUMB_YIELD_MS`）。两个限制保证它不会走极端：

- **只在"看图片"时让路**：大图界面，或者已经进到某个子文件夹里。
  停在顶层相册列表时不让——那张列表本身就是扫描在长出来的，让路只会让它自己变慢。
- **一次最多让 2.5 秒**（`SCAN_YIELD_MAX_MS`），然后至少读完一个目录；所以
  一直翻图的极端情况下，扫描是"大幅降速"，而不是停死。图片一停，它立刻恢复全速。

测试环境：Windows 11 / 150% 缩放 / i7 笔记本 + RTX 5060 / 素材为 900×900 PNG，
分「800 文件 / 40 目录」「15030 文件 / 126 目录」「1200 文件夹 / 3600 文件」三档。

上面那一档的素材不用另外找，仓库里有个生成器：

```
python tools/make_bench.py _bench2 15000 126     # 约 600 MB，一分钟左右
FastPeek.exe --bench "%CD%\_bench2"
```

`_bench2/` 只是压测用的临时目录，测完可以直接删掉（已在 `.gitignore` 里）。

## 源码结构

不是为了凑文件数，是为了以后改的时候不用在三千行里翻：

```
src/app.h       公共类型与全部对外函数声明（唯一头文件）
src/core.c      DPI、文字绘制、路径、自然排序、设置读写、文件夹选择框
src/scan.c      后台扫描线程（FindFirstFileEx + 大目录优化，最多两层子文件夹），增量通知 UI
src/folders.c   子文件夹索引：目录分组、卡片预览、路径前缀判断
src/image.c     WIC 解码（含 JPEG DCT 直缩、EXIF 转正、透明合成）、两级缓存、相邻图预加载
src/thumbcache.c 磁盘缩略图缓存（路径 hash → %LocalAppData%\FastPeek\thumbs\*.tc）
src/video.cpp   MFPlay 嵌入播放（动态加载 mfplay.dll，缺了也不影响启动）
src/view.c      缩略图网格 / 子文件夹卡片 / 大图舞台：布局、命中测试、缩放平移、滚动条
src/chrome.c    自绘工具栏与状态栏
src/main.c      窗口过程、命令分发、快捷键、全屏、启动流程
```

几条贯穿全局的约定：

- 只有一个刷新入口 `AppInvalidate()`，一个信息栏更新入口 `AppUpdateInfo()`，
  一个命令入口 `DoCommand(BtnId)`——加一个按钮只需要动 `kSpec[]` 和 `switch` 各一处。
- 所有像素尺寸都过 `S()`（DPI 缩放），150% / 200% 缩放下不会错位。
- 缩略图缓存用 **LRU 槽位**（160 格，单张压到格子尺寸后约 200 KB，上限约 32 MB），
  按"最后用到"淘汰而不是按字节记账，4K 屏和大目录都不会把内存吃穿。
- 删除文件、重命名这类破坏性操作一律不做——看图器不该有误删的风险。

## 崩溃自诊断

万一崩了，程序会在 exe 旁边写两个文件帮你定位：

- `FastPeek-crash.log` —— 文本日志，记录异常码、崩溃地址和**调用栈**
  （每一帧都标出「哪个模块 + 偏移」，不装调试器也能反查到出错函数）。
- `FastPeek-crash.dmp` —— 完整内存转储，可用 WinDbg / Visual Studio 打开看现场。

把 `FastPeek-crash.log` 的内容发出来（或直接丢给 AI），就能知道是哪个函数、
哪一行把程序带崩的，而不是靠"闪退"两个字猜。

## 已知限制

- 大图解码上限 4096 px（长边）。再大的图会缩到这个尺寸再显示——为了秒开，
  代价是 8K 全景图看不到 100% 的每个像素。
- 只索引**两层**子文件夹（见上文「扫描的范围」）：第 3 层往下的照片不会出现在
  卡片计数和「整个文件夹」里；要看它们，在那个位置按 `O` 把里层文件夹当成新的根打开。
- 视频走系统解码器，不支持的容器（比如没装扩展的 HEVC/MKV）需要按 `E` 外挂播放器。
- 视频播放时有进度条（在底部状态栏），点击或拖动即可跳转；部分直播/无时长信息的流
  没有总时长，此时进度条不显示时间。
- 上万文件的目录里，缩略图是"滚到哪解到哪"的：快速甩到没去过的位置，会先看到占位符
  再逐格出图（解码在后台线程做，所以出图慢一点，但滚动本身不掉帧）。
  停下来约 120 ms 才开始读盘，快速甩过的格子一次都不会被碰；后台队列只保留两屏，
  超出就丢掉最旧的那条请求，不会去读早就滚出屏幕的文件。
- 后台扫描和出图共用一根盘，所以**在还没扫完的目录里点进子文件夹**时，
  扫描会先让路给图片（见上文"扫描给图片让路"）——这段时间顶层卡片列表会长得慢一些，
  等图片读完立刻恢复。反过来，停在顶层列表时扫描不让路。
- 视频封面比图片贵得多（一帧约 80 ms，要 demux + 解码 + 缩放），所以它走后台线程，
  滚动时不会等它：先出黑卡片加播放按钮，停下来之后封面再逐格补上。快速甩动时
  还会**暂时暂停**封面请求（约 120 ms 静止后才恢复），避免一次性把几百个格子的
  封面全塞进后台队列。
- 子文件夹卡片上的封面取的是那个文件夹里**路径排序最前的那张图片**；纯视频文件夹
  没有画面，只显示文件夹图标和文件数，点进去才看得到视频封面。
- 后退只记位置，不记滚动历史：每个进过的网格记一个"滚到哪儿、选的是谁"，
  回到那一层就复原；同一层再进一次就是新的记录了。
- 卡片列表只列出"里面确实有图片或视频"的子文件夹，空目录不占位置。
- 只列出图片和视频，不显示文档、压缩包等其他文件。
- 不做删除、重命名、旋转后保存——只读，改不了原文件。
- 相邻图预加载只在**大图**里工作，最多占 96 MB；离开大图、切换目录时立刻释放。
  大于 48 MB 的解码结果（例如 4096×4096）不预加载，按 → 时走正常解码。
- `Ctrl+C` 复制的是程序解码后的像素（长边最大 4096），不是原始文件的字节；
  要原图请复制路径后用别的程序打开。透明图会带着棋盘格底色，因为屏幕显示的就是它。
- 信息浮层只对图片生效；视频画面由系统 EVR 直接输出，无法在同一个表面上叠字。
- 搜索匹配的是文件名（不含目录名），范围就是当前已经扫描到的两层；切换目录会清空，
  想接着搜同一个词需要重新输入。
- 幻灯片只播放图片：放到最后一张自动结束，下一项是视频时也会停在那个视频上，
  不会替你把视频播完。
